## Architecture Overview

### Service Topology
```
Windows SCM
 ├── AttackLensWatchdog (watchdog_svc.py)
 │    └── Monitors AttackLensAgent; restarts on failure (max 5 in 5 min)
 └── AttackLensAgent (service.py → win_agent.py)
      ├── _enroll_if_needed()  → POST /api/v1/enroll (once per machine)
      ├── collector threads × 27 sections → circuit-breaker guarded
      ├── sender thread         → POST /api/v1/ingest with AES-256-GCM envelope
      └── heartbeat thread      → agent_health every 60s
```

### Security Model
- **Transport:** TLS 1.3 minimum (enforced by `tls_transport.py`)
- **Encryption:** AES-256-GCM per payload; HMAC-SHA256 over full envelope
- **Key derivation:** HKDF-SHA256 → enc_key + mac_key (in `agent/agent/crypto.py`)
- **Key storage:** DPAPI Credential Manager → DPAPI file → ACL-restricted file
- **Enrollment:** `/api/v1/enroll` (open enrollment); manager returns 64-hex API key
- **Replay defence:** ±300s timestamp window + per-nonce dedup (server-side)

### Config Path
```
C:\ProgramData\AttackLens\config\agent.toml

C:\ProgramData\AttackLens\logs\agent.log
C:\ProgramData\AttackLens\spool\win_agent.spool.ndjson
```

## Bugs Fixed (2026-05-16)

### 1. `agent/agent/auto_enroll.py` — Wrong default security dir (Jarvis branding)
**File:** `agent/agent/auto_enroll.py:140`  
**Was:** `security_dir = _os.path.join(base, "Jarvis", "security")`  
**Now:** `security_dir = _os.path.join(base, "AttackLens", "security")`  
**Impact:** Without this fix, `client.key` was stored in `C:\ProgramData\Jarvis\security\` but agent.toml points to `C:\ProgramData\AttackLens\security\`. The agent would re-enroll every restart.

### 2. `agent/os/windows/keystore.py` — Credential Manager service name (Jarvis branding)
**File:** `agent/os/windows/keystore.py:103`  
**Was:** `_CM_SERVICE = "com.jarvis.agent"`  
**Now:** `_CM_SERVICE = "com.attacklens.agent"`  
**Impact:** Keys stored under the old service name would not be found on load, causing re-enrollment every restart.

### 3. `agent/os/windows/tls_transport.py` — User-Agent header (Jarvis branding)
**File:** `agent/os/windows/tls_transport.py:253`  
**Was:** `"User-Agent": "jarvis-agent-win/2.0"`  
**Now:** `"User-Agent": "attacklens-agent-win/2.0"`  
**Impact:** Manager logs and any User-Agent filtering would see wrong client identity.

### 4. `agent/agent/enrollment.py` — User-Agent header (macIntel branding)
**File:** `agent/agent/enrollment.py:164`  
**Was:** `"User-Agent": "macintel-agent/2.0"`  
**Now:** `"User-Agent": "attacklens-agent/2.0"`  
**Impact:** Enrollment POST showed wrong agent identity to manager.

### 5. `agent/agent/client_key.py` — Stale branding in serialized file
**File:** `agent/agent/client_key.py:170-172`  
**Was:** `"# Jarvis Agent Identity\n"` + `"restart the JarvisAgent service"`  
**Now:** `"# AttackLens Agent Identity\n"` + `"restart the AttackLensAgent service"`  
**Impact:** Written into `client.key` on every enrollment — cosmetic but confusing.

### 6. `pkg/attacklens-agent.spec` — Missing PyInstaller hidden imports
**File:** `agent/os/windows/pkg/attacklens-agent.spec`  
**Added:** `agent.agent.auto_enroll`, `agent.agent.client_key`  
**Impact:** PyInstaller bundles only what it can statically trace. `auto_enroll` is called
via `from agent.agent.auto_enroll import get_or_enroll` inside `win_agent.py._enroll_if_needed()`.
`client_key` is imported by `auto_enroll.py`. Without these in `hiddenimports`, the built EXE
would crash at first startup with `ModuleNotFoundError: No module named 'agent.agent.auto_enroll'`.

### 7. `normalizer.py` — Missing `eventlog` normalizer
**File:** `agent/os/windows/normalizer.py`  
**Added:** `_eventlog()` function + entry in `_NORMALIZERS` dispatch table  
**Impact:** `eventlog` section was collected (300s interval, `EventLogCollector`) but `normalize()`
returned raw collector output unchanged. The normalizer now coerces field types and filters
invalid records (same contract as all other normalizers).

## WiX MSI Property Reference

| Property | Default | Description |
|----------|---------|-------------|
| `MANAGER_IP` | `localhost` | Manager hostname or IP (no scheme, no port) |
| `MANAGER_PORT` | `8443` | Manager port (8443 for dev, 443 for prod) |
| `TLS_VERIFY` | `false` | `true` → https + cert validation; `false` → http + no cert check |
| `ENROLL_TOKEN` | _(empty)_ | Enrollment token from manager; empty = open enrollment |
| `AGENT_NAME` | `%COMPUTERNAME%` | Human label shown in manager dashboard |
